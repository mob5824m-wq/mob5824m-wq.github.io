01 Overview & Privacy Principles

This Privacy Policy describes how the Punishment Manager Discord bot (“the Bot”, “we”, “us”) handles information when you add it to your Discord server or interact with it.

Our core architectural principle is strict data minimization: Punishment Manager only processes and stores the absolute minimum Discord Snowflake IDs and metadata necessary to manage temporary role assignments, countdown expiration timers, and audit logs.

We do not monetize your data, sell personal information, or run analytics trackers. Punishment Manager is designed purely to automate server moderation duties efficiently and transparently.

02 Information We Collect & Store

When Punishment Manager is configured and invoked in a Discord server, the following data is stored locally in the bot’s SQLite database:

Data Point Type Purpose & Usage
Guild (Server) ID Discord Snowflake (integer) Identifies which Discord server the configuration and moderation records belong to.
User ID Discord Snowflake (integer) Identifies the punished user and the moderator who initiated the action.
Configured Role IDs Discord Snowflake (integer) Stores the server's designated punish role, post-punish role, and optional staff role IDs.
Channel ID Discord Snowflake (integer) Stores the target text channel ID where staff logging embeds are dispatched.
Timestamps Unix timestamp / ISO-8601 string Records when the punishment was issued, target expiration time, and completion timestamp.
Reason Text string (optional) Stores the moderator-provided reason (e.g., “Rule 3 violation — spamming”) included in embeds.
Resolution Status Enum / String Indicates how the case ended: timer_expired or pardoned.

03 Data We Do NOT Collect

To avoid doubt and respect your privacy, Punishment Manager does NOT collect, read, or store:

  • Chat Messages: The bot does not log or monitor general channel conversations, user chats, or message history. Only explicit slash command invocations are processed.
  • Private Direct Messages: The bot never reads your personal DMs. When configured, it only sends a single automated outgoing notification embed to the punished member.
  • IP Addresses & Hardware Info: The bot operates via the official Discord Gateway API and has no access to user IP addresses, location data, or device hardware details.
  • Personal Identifiers: We do not ask for or collect real names, email addresses, phone numbers, passwords, or financial payment information.
  • Voice Data: The bot does not connect to voice channels or record audio streams.

04 How Information is Used

The collected data is used exclusively to provide the Bot’s core functionality:

  1. Timer Scheduling: Calculating remaining punishment duration and scanning active cases every 10 seconds to transition roles on time.
  2. Embed Dispatch: Populating rich embed fields sent to the configured staff channel and to the user via DM.
  3. Moderation Audit History: Providing servers with a transparent audit log via /punish status [user] so staff can review past moderation actions.
  4. State Recovery: Restoring active punishment schedules following a bot reboot or server maintenance window.

05 Data Storage & Retention

Storage Architecture: All data is stored in a localized SQLite database (punishments.db) managed on the host server where the Bot instance is executing.

Retention Period:

  • Active Punishments (punishments table): Retained only while the punishment is in progress. As soon as the timer expires or a moderator executes /punish pardon, the active entry is removed.
  • Punishment History (punishment_history table): Retained as an audit log for server moderation records. Guild administrators may request deletion at any time.
  • Guild Configuration: Retained while the bot is present in the server to maintain setup settings.

06 Third-Party Data Sharing

We never sell, rent, trade, or share user data with third parties.

Data is transmitted exclusively across the official Discord API to execute role modifications and send messages, subject to Discord’s own Privacy Policy.

07 Your Rights, Data Access & Deletion

We fully respect your data privacy rights under applicable data protection laws (such as GDPR, CCPA/CPRA, and Canadian PIPEDA):

  • Right to View / Access: Any member can view their recorded history in a server using the /punish status [user] slash command.
  • Right to Deletion (Right to be Forgotten): Users or server administrators can request the complete purge of their stored Discord ID and associated case history from the database.
  • Guild Purge: When a server kicks or bans the bot, administrators may request a full deletion of all guild records and history.

To submit a data access or deletion request, please email mob5824@duck.com with your Discord User ID or Guild ID. Requests are processed within 14 business days.

08 Security Safeguards

We implement industry-standard security measures to safeguard data:

  • Token Protection: Bot tokens are masked on input during interactive setup (using termios on Unix and msvcrt on Windows) and stored with restrictive file permissions (0600).
  • Parameterized Queries: Database interactions use parameterized SQLite queries to protect against SQL injection vulnerabilities.
  • Access Control: Only server administrators and authorized staff can trigger management commands.

09 Children’s Privacy

Punishment Manager complies with Discord’s Age Guidelines and the Children’s Online Privacy Protection Act (COPPA). The Bot does not knowingly collect or solicit personal information from children under the age of 13. If you believe a child under 13 has provided personal data, please contact us for immediate deletion.
